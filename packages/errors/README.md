# @package/errors

Framework-agnostic error handling package with centralized registry, type-safe factory methods, and i18n support.

## Overview

`@package/errors` is a comprehensive error handling system designed for enterprise applications. It provides:

- **Centralized Error Registry** - All error codes defined in one place with type safety
- **Type-Safe Factory Methods** - Autogenerated factory for creating errors with full TypeScript support
- **i18n Support** - Multi-language error messages with dynamic locale discovery
- **Framework Agnostic** - Works with NestJS, Next.js, vanilla Node.js, or any TypeScript project
- **Parameter Interpolation** - Dynamic error messages with contextual values
- **HTTP Status Mapping** - Automatic HTTP status code mapping for API responses

## Features

- **72 Predefined Error Codes** across 8 domains (User, Auth, Validation, Database, Business, External, File, System)
- **2 Built-in Locales** - English (en), Arabic (ar-SA)
- **Dynamic Locale Loading** - Add new languages by creating locale files, no code changes needed
- **Immutable Error Objects** - Errors are deeply frozen for safety
- **Development Warnings** - Automatic deprecation warnings for outdated error codes
- **Comprehensive TypeScript Types** - Full type safety and autocomplete support
- **BaseResponseDto Integration** - Unified error response types for consistent API responses
- **Framework Agnostic** - Works with NestJS, Next.js, Express, or any TypeScript framework

## Quick Start

### Installation

```bash
pnpm add @package/errors
```

### Basic Usage

```typescript
import { Errors } from '@package/errors';

// Step 1: Throw an error using the factory
throw Errors.useruserWithId001({ userId: '123' });

// Step 2: In your API/error handler, translate the error
import { TranslationService } from '@package/errors';

await TranslationService.initialize();
const translation = await TranslationService.translateAsync(
  'USER_001',
  { userId: '123' },
  { locale: 'ar-SA' }
);

console.log(translation.message);
// Output: "المستخدم بالمعرف 123 غير موجود" (Arabic)
```

### With Metadata

```typescript
throw Errors.validationvalidationFailedField001(
  { field: 'email' },
  { requestId: 'abc-123', userId: '456' } // metadata for debugging
);
```

### With BaseResponseDto (Unified Error Responses)

```typescript
import { BaseResponseDto } from '@/common/dtos';
import { ErrorResponseData, ErrorResponseMetadata } from '@package/errors';

// In your error handler
const errorData: ErrorResponseData = {
  code: error.code,
  message: error.message,
  translated: translation.message,
  parameters: error.parameters
};

const errorMetadata: ErrorResponseMetadata = {
  timestamp: new Date().toISOString(),
  requestId: request.headers['x-request-id'],
  error: {
    category: error.definition.type,
    severity: error.definition.severity,
    httpStatus: error.httpStatus
  }
};

return BaseResponseDto.error(errorData, errorMetadata);
```

See [Response Types](./docs/response-types.md) for complete documentation on unified error responses.

## Two-Step Error Handling

The package follows a two-step pattern for error handling:

### Step 1: Throw Errors

Throw errors anywhere in your application using the `Errors` factory:

```typescript
// In a service or command handler
async getUser(userId: string) {
  const user = await this.userRepository.findById(userId);
  if (!user) {
    throw Errors.useruserWithId001({ userId });
  }
  return user;
}
```

### Step 2: Catch and Translate

In your error handler/middleware, catch and translate errors:

```typescript
// In your global error handler
catch (error) {
  if (error instanceof RegisteredError) {
    const translation = await TranslationService.translateAsync(
      error.code,
      error.parameters,
      { locale: detectLocaleFromRequest(request) }
    );

    return {
      code: error.code,
      message: translation.message,
      statusCode: error.httpStatus,
      timestamp: error.timestamp,
    };
  }
}
```
